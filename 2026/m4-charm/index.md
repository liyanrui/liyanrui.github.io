m4 语言及其处理器诞生于约半个世纪之前，那时是上古 Unix 的洪荒年代，后来在 GNU/Linux 系统中传续和发展。当你写出第一个能被 GNU m4 展开的宏时，也许它只能替换最为简单不过的文本，可是兴许你应该能感受到一些遥远的苍凉。我不知道，这种微型的宏编程语言在现代对于你而言是否还有学习的意义，我只知道，陶埙这种原始的乐器，在今天依然能吹奏动人的音乐。

# 初入法门

这世上有成百上千种编程语言，每种语言都可以从编写一个能在计算机屏幕上输出 `Hello world!` 文字的简单程序开始学起。用 m4 语言写这个程序，大概在所有语言中最为简单，只需新建一份文件，假设其名为 hello.m4，令其内容为

```m4
Hello world!
```

然后，在终端（命令行环境）里且在 hello.m4 文件所在目录执行 GNU m4 命令，

```console
$ m4 hello.m4
```

便可在屏幕上输出 `Hello world!`。

在上述示例中，hello.m4 是 m4 处理器的输入文件。该文件的内容流入 m4 处理器，再流出，其内容不变，而 m4 处理器默认会将内容流出至计算机屏幕——确切而言，是计算机标准输出设备——，故而能在屏幕上显现 `Hello world!`。

若想让文本在流入和流出 m4 后发生变化，需要定义一些宏，并调用它们。例如，将 hello.m4 的内容修改为

```m4
define(Hello, 你好)
define(world, 世界)
Hello world!
```

再次像上述那样执行 m4 命令，得到的输出为

```


你好 世界!
```

在上述示例里，`Hello` 和 `world` 皆被定义为宏，而 `Hello world!` 语句调用它们。在文本流入 m4 处理器的过程中，遇到普通文本，m4 处理器会将其直接发送至输出流，遇到宏调用语句，m4 处理器会将其展开为宏的定义，然后将结果发送至输出流，于是便得到了上述中文输出。

需要注意，上述输出的中文文本之前存在两个空行，它们是 `define` 语句末尾的换行符形成的。`define` 语句本身也是宏调用语句，只是其展开结果为空文本，而其后的换行符是输入流中的普通文本，会被 m4 处理器发送到输出流，从而形成了两个空行。

使用 `dnl` 宏可以删除 `define` 语句之后的换行符，例如

```m4
define(Hello, 你好)dnl
define(world, 世界)dnl
Hello world!
```

流过 m4 处理器后，可得

```
你好 世界!
```

`define` 和 `dnl` 皆为 m4 语言的内建宏，前者用于定义宏，后者用于删除同一行中位于其后的所有文本，包括换行符。由于 `dnl` 具备删除文本的能力，故而在使用 m4 语言编写代码时，可以用它作为注释符使用，例如

```m4
define(Hello, 你好)dnl 定义 Hello 宏
define(world, 世界)dnl 定义 world 宏
dnl 调用 Hello 和 world 宏
Hello world!
```

上述文本流过 m4 处理器，所得结果依然是

```
你好 世界!
```

不过，没办法定义中文宏，例如

```m4
define(你好, Hello)dnl
define(世界, world)dnl
你好 世界!
```

流过 m4 处理器，得到的依然是

```
你好 世界!
```

原因很简单，m4 语言只允许使用英文字母、下划线和数字构造宏名，用其他字符构造的宏名是无效的。此事怨不得 m4 语言，在它诞生之后的很多年里，其处理器赖以生存的计算机世界一直没有出现汉字。

> 确切而言，m4 的宏名以字母或下划线开头，后跟字母、数字或下划线，亦即宏名不能以数字开头。这种命名规则与 C 语言一致，大概并非出于巧合，而是因为 m4 的发明者皆与 C 语言渊源颇深，其一是 Unix 名宿 Brian Kernighan，其代表著作是《C 程序设计语言》，另一位干脆是 C 语言之父 Dennis Ritchie。


# 野马也，尘埃也

从现在开始，我将 m4 处理器简称为 m4。有时，我也会将 m4 语言简称为 m4。有上下文的存在，二者应该不会出现混淆。

对于新手而言，m4 的宏，状如野马，不小心就会摔得七荤八素，兴许还能让 m4 失去意识。例如，当

```m4
define(hello, hello world!)dnl
hello
```

流过 m4 时，会致其僵死，需要以 `Ctrl + c` 键终止。

发生了什么呢？m4 在展开 `hello` 宏调用语句时，得到 `hello world!`，然后 **m4 会对宏调用语句的展开结果再次扫描，若遇到宏调用语句则继续予以展开**，于是 `hello world!` 中的 `hello` 会被展开，又得到 `hello world!`……这个过程无有穷尽，m4 陷入其中。

要避免 m4 对宏调用语句的展开结果再次展开，需要用引号对文本加以保护。m4 的引号，状若尘埃……左引号是 <code>\`</code>，右引号是 <code>'</code>，不小心很容易看不到它们，或者很小心去看它们，又容易看不清有多少……将上述文本修改为

```m4
define(hello, `hello world!')dnl
hello
```

将其再度流过 m4，得到

```
hello world!
```

……那是不可能的！m4 依然会进入僵死状态，原因是，**m4 处理器遇到带引号的一段文本，会将其最外层的引号脱去，将剩余文本发送至输出流。**这意味着，在上述示例中，m4 在处理 `define` 语句时，便已经将 `hello world!` 外围的引号脱去了，所以 `hello` 的展开结果依然会导致 m4 陷入到无有穷尽的 `hello` 展开过程。

既然最外层的引号会被 m4 处理器脱除，若在 `hello` 的定义里再加一层引号，

```m4
define(hello, ``hello world!'')dnl
hello
```

第一层引号会在 m4 处理 `define` 语句时脱去，于是 `hello` 的展开结果是

```
`hello world!'
```

这个结果对于 m4 而言，是再次遇到带引号的文本，将引号脱去，将剩余结果发送至输出流，于是最终结果便是

```
hello world!
```

在定义宏时，宏的名字有时未必如你所见。例如

```m4
define(foo, `Foo')dnl
define(foo, `-Foo-')dnl
foo Foo
```

请问上述文本的展开结果是什么？`foo` 宏被定义了多次，以最后一次定义为准，于是 `foo` 的展开结果为 `-Foo-`。`Foo` 不是宏，会被 m4 原样发送至输出流。上述文本的展开结果为

```
-Foo- Foo
```

……倘若你也觉得应当是这个结果，需要恭喜你有机会更深入地理解 m4 宏了。这个答案是错的，正确的答案是无数个 `-` 形成的文本，无有穷尽，原因是，第 2 个 `foo` 的定义语句里，宏名 `foo` 未加引号抑制，m4 会将其视为宏调用语句，于是该定义语句在 m4 看来，实际上是

```m4
define(Foo, `-Foo-')
```

亦即第 2 个 `foo` 定义语句所定义的宏实际上 `Foo`。然后，m4 处理文本 `foo Foo`，其中 `foo` 被展开为 `Foo`。m4 发现 `Foo` 是宏调用语句，继续展开，结果得到 `-Foo-`，而该结果里又有 `Foo`，于是 m4 继续将其展开，结果便是 `--Foo--`……这个过程也是无有穷尽的，所以 m4 会陷入不断展开 `Foo` 的过程里，我们能看到的是 m4 疯狂输出 `-` 字符，但是永远都看不到 `Foo`，因为它一直在被展开着。

倘若将上述文本修改为

```m4
define(`foo', `Foo')dnl
define(`foo', `-Foo-')dnl
foo Foo
```

令其流过 m4，便如上文所想，第 1 个 `foo` 定义会被第 2 个 `foo` 定义取代，结果为

```
-Foo- Foo
```

在定义 m4 宏时，要有意识地使用引号抑制文本，使其不会被 m4 在不经意间展开了。一旦你领悟了 m4 宏的定义和引号的用法……大概就能明白庄子所说的，野马也，尘埃也，生物之以息相吹也。

上述示例定义的宏皆无参数，m4 宏可以有参数。在宏定义中，参数以 `$1`，`$2`，... 表示，例如

```m4
define(`foo', `![$1]($2)')dnl
foo(`插图 1', `a.png')
```

展开结果为markdown 的插图标记，

```
![插图 1](a.png)
```

现在，想必你已经很习惯在宏的定义和调用语句中使用引号了。**m4 引号的使用有一个基本原则，括号每多一层，引号便可多加一层。若是存在宏的递归调用，引号还需要再额外增加一层。**

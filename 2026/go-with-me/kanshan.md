好，那我试着从你最熟悉的视角讲——把 HTTP 请求想象成一个 C 程序收到的数据包。

一个 HTTP 请求本质上就是一段文本

李雷在浏览器地址栏敲入 http://你的IP:8080/ 然后回车，浏览器会向你的机器发送一段文本，大概长这样：

GET / HTTP/1.1
Host: 你的IP:8080
（其他头部...）

注意第一行的 GET，以及最后有一个空行（\r\n\r\n）。这就是一个"没有 body"的请求——头部之后什么都没有。

而当李雷在表单里输入"韩梅梅"并点击"提交"时，因为你的 HTML 写的是 ，浏览器发送的文本变成了：

POST / HTTP/1.1
Host: 你的IP:8080
Content-Type: application/x-www-form-urlencoded
Content-Length: 17

from-lilei=韩梅梅

关键区别就两个：

1. 第一行从 GET 变成了 POST；
2. 头部空行之后多了一段 body：from-lilei=韩梅梅。

GET 请求的 body 是空的。浏览器访问页面时默认用 GET，只发头部，不发 body。

Go 的 r.FormValue 在做什么

FormValue("from-lilei") 就是去请求里找名为 from-lilei 的值。它先查 body（POST 才有），找不到再查 URL 里的 query string（就是地址栏里 ? 后面的部分，比如 /?from-lilei=xxx）。

所以李雷第一次访问页面——GET 请求，body 为空，URL 里也没有 ?from-lilei=...——FormValue 自然返回空字符串。这个行为和你文章里写的结论完全一致，只是背后的原因是"GET 请求根本没带 body"，而不是"输入框里还没填东西"。

一个不太精确但直觉上好理解的类比

你可以把 HTTP 请求想成 scanf。GET 像是只给了你一个函数名但没传参数，POST 像是函数调用时带了实参。表单提交就是浏览器帮你把"实参"塞进了请求的 body 里，格式是 字段名=值。
